\section{Corrections and Calibrations}
\label{sec:corrections}

Corrections are applied in a fixed order: the collaboration's data performance group
corrections first, then analysis-specific corrections where a
data/MC discrepancy exists.

\subsection{Collaboration-recommended corrections}
\label{sec:corrections:recommended}

\paragraph{Track momentum scale and energy loss.}
Applied during reconstruction from the
\texttt{tracking\_release08\_20260119\_EnergyMomentumScale} global tag, with
separate payloads for data and simulation and the \texttt{central} scale
factor (Sec.~\ref{sec:recon:fsp}).
These are applied to the track momenta rather than as an event weight, so
they propagate into every derived quantity, including both fit observables.

\paragraph{Particle identification.}
Applied offline by \texttt{utilities.apply\_pid\_corrections()} through the
systematics-corrections framework.
Twelve tables are read per run period: efficiency and fake-rate tables for the
lepton of the channel, for the kaon, and for the pions, covering the
misidentification sources relevant to the $K\pi\pi\ell$ final state.
Each particle receives a weight and the four are multiplied into a single
per-event weight.

The performance corrections are run-dependent.
In the electron channel the corrections are evaluated on the \emph{pre}-bremsstrahlung
quantities (\texttt{ell\_BFbrems\_}), because the 
\texttt{electronIDNN} tables are produced without bremsstrahlung correction; this is the
same reason the electron momentum requirement is applied before the correction
(Sec.~\ref{sec:recon:fsp}).


\subsection{Analysis-specific corrections}
\label{sec:corrections:specific}

The generic-$B\bar{B}$ reweighting of Sec.~\ref{sec:bbbar} is the only
analysis-specific correction currently derived.
It is applied as a per-event weight multiplying the base weight, the PID
weight and, for a combined-run fit, the run-dependent factor.

\subsection{Corrections not implemented}
\label{sec:corrections:notnominal}

Four further corrections exist in the analysis library and are not part of the
nominal chain.
They are recorded here so that they are not mistaken for applied corrections.

\paragraph{Slow-$\pi^{0}$ efficiency.}
\texttt{utilities.apply\_pi0\_eff\_correction()} merges a momentum and polar
angle binned data/MC ratio table onto the $\pi^{0}$ of the $D^{*}$ veto.
The correction needs an updated MC16rd table, which is why the $D^{*}$ veto
region is not yet used quantitatively (Sec.~\ref{sec:recon:dstveto}).
We currently use the table
\texttt{MC16\_sys\_tables/pi0\_eff50\_corr.csv}, which is derived from MC15rd data
and simulation rather than MC16rd; it is used only as a testing input for the
$D^{*}$-veto data/MC agreement check, since the analysis data and simulation
are Proc16 and MC16rd.

\paragraph{Tracking corrections.}
The small tracking efficiency corrections have not yet been applied. This requires
another run through the full data.
\vspace{2mm}

\InProgress{form-factor reweighting is not yet implemented.} 
The signal, normalization and $D^{**}$ templates therefore carry the generator
form factors.  We plan to reweight to a current
parameterization with HAMMER, as used in other Belle~II semileptonic
analyses; this correction is expected to be small
for this analysis, and its systematic effect has been manageable in
other semileptonic Belle~II analyses.
