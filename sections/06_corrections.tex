\section{Corrections and Calibrations}
\label{sec:corrections}

Corrections are applied in a fixed order: the collaboration-recommended
corrections first, then analysis-specific corrections derived only where a
data/MC discrepancy persists after them.
The ordering matters because an analysis-specific correction derived before
the recommended ones would absorb part of an effect that the recommended
correction is meant to remove, and the two would then double count.

\subsection{Collaboration-recommended corrections}
\label{sec:corrections:recommended}

\paragraph{Track momentum scale and energy loss.}
Applied during reconstruction from the
\texttt{tracking\_release08\_20260119\_EnergyMomentumScale} global tag, with
separate payloads for data and simulation and the \texttt{central} scale
factor (Sec.~\ref{sec:recon:fsp}).
These act on the track momenta themselves rather than as an event weight, so
they propagate into every derived quantity, including both fit observables.

\paragraph{Particle identification.}
Applied offline by \texttt{utilities.apply\_pid\_corrections()} through the
systematics-corrections framework.
Twelve tables are read per run period: efficiency and fake-rate tables for the
lepton of the channel, for the kaon, and for the pions, covering the
misidentification sources relevant to the $K\pi\pi\ell$ final state.
Each particle receives a weight and the four are multiplied into a single
per-event weight.

Two features of this correction are analysis-relevant.
It is run dependent, and is therefore evaluated before run periods are
concatenated, so that combining Run~1 and Run~2 does not average two different
corrections.
And in the electron channel it is evaluated on the \emph{pre}-bremsstrahlung
quantities (\texttt{ell\_BFbrems\_}), because the collaboration produces the
\texttt{electronIDNN} tables without bremsstrahlung correction; this is the
same reason the electron momentum requirement is applied before the correction
(Sec.~\ref{sec:recon:fsp}).

\subsection{Analysis-specific corrections}
\label{sec:corrections:specific}

The generic-$B\bar{B}$ reweighting of Sec.~\ref{sec:bbbar} is the only
analysis-specific correction currently derived.
It is applied as a per-event weight multiplying the base weight, the PID
weight and, for a combined-run fit, the run-dependent factor.

The fake-$D$ normalisation is a special case and is the one place where a
double application is plausible, so it is stated explicitly.
The run-dependent factor ($0.87$ for Run~1, $1.0$ for Run~2) is a
\emph{fixed input} to the generic-$B\bar{B}$ tuning, where it holds the
fake-$D$ component at its externally determined level while the
generic-$B\bar{B}$ families are fitted.
It is deliberately \emph{not} applied when the fit templates are built: in the
fit the fake-$D$ normalisation is a free parameter determined by the $D$-mass
sideband channel (Sec.~\ref{sec:fit:modifiers}).
Applying the factor in both places would count it twice.

\subsection{Corrections implemented but not in the nominal chain}
\label{sec:corrections:notnominal}

Two further corrections exist in the analysis library and are not part of the
nominal chain.
They are recorded here so that they are not mistaken for applied corrections.

\paragraph{Slow-$\pi^{0}$ efficiency.}
\texttt{utilities.apply\_pi0\_eff\_correction()} merges a momentum and polar
angle binned data/MC ratio table onto the $\pi^{0}$ of the $D^{*}$ veto.
It is called only from the normalisation plotting notebooks
(\texttt{Notebooks/Plotting/2\_Plot\_norm\_*}), not from the template or fit
code, so it affects validation plots and not the fit.
Candidates falling outside the table binning receive a neutral weight of unity
and are reported.
The correction awaits an updated MC16rd table, which is why the $D^{*}$ veto
region is not yet used quantitatively (Sec.~\ref{sec:recon:dstveto}).
The table currently passed to it by the normalisation plotting notebooks,
\texttt{MC16\_sys\_tables/pi0\_eff50\_corr.csv}, is derived from MC15rd data
and simulation rather than MC16rd; it is used only as a testing input for the
$D^{*}$-veto data/MC agreement check, since the analysis data and simulation
are Proc16 and MC16rd.
A second folder, \texttt{MC16\_sys\_tables/slow\_pi0/}, is not used anywhere
in the analysis at the pinned commit.

\paragraph{Naive binned data/MC ratio.}
\texttt{utilities.create\_naive\_data\_mc\_correction()} builds a per-bin
data/MC ratio in a single variable.
It is defined but called nowhere in the repository at the pinned commit,
and is now marked as such by a comment in the source
(\texttt{utilities.py}, above \texttt{create\_naive\_data\_mc\_correction}).
It is being kept for now on the chance it is useful later, rather than
removed (\texttt{ANALYSIS\_DECISION}); a binned data/MC ratio applied to a
variable correlated with the fit observables would bias the fit, so if it is
eventually called, its intended scope should be stated at that point.

The safeguard against double application is structural rather than procedural:
each correction is carried as its own named column, and the histogram-filling
helper multiplies a fixed, explicit list of columns.
A correction can therefore only be applied twice if it is written into two
different columns, or if a column is multiplied in twice.
The weakness of this design is the complement: because a column absent from
the frame is silently skipped rather than raising, a correction can be
\emph{omitted} without any diagnostic.

raising an error if a correction expected to be applied is absent.  Neither
is implemented yet.  The base weight of Sec.~\ref{sec:data:weights} is the
case where this matters most, since it is the column most likely to be
silently absent or reused for the wrong purpose}
